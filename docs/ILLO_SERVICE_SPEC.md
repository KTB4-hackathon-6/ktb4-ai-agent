# ILLO 서비스 기능 명세

- 문서 상태: 구현 전 컨펌용
- 작성일: 2026-08-20
- 초기 대상: 제조업·건설업·서비스업·농축산업·어업 E-9 외국인 근로자
- 지원 민원: 노동포털 `SN001` 진정서

## 1. 서비스 정의

ILLO는 외국인 근로자가 근로계약서와 보유한 급여명세서를 업로드하면 주요 근로조건과 확인이 필요한 문제를 설명하고, 실제 근무 상황에 대한 모국어 진술을 문서와 비교한다. 사용자가 선택한 경우 진정서 작성과 공식 신고 경로 확인까지 돕는 권리구제 준비 서비스다.

서비스의 최종 산출물은 다음 네 가지다.

1. 계약서·급여명세서·사용자 진술의 비교 결과와 쉬운 모국어 설명
2. 고용주 확인 요청문, 상담용 차이표와 추가 증거자료 안내
3. 사용자가 검토·수정할 수 있는 `SN001` 진정서 HWPX 초안
4. 사용자가 직접 접수하거나 문의할 수 있는 문제 유형별 공식 기관 정보

ILLO는 상담사를 연결하거나 진정서를 대신 제출하지 않는다.

## 2. 전체 사용자 흐름

```text
[문서 업로드]
  근로계약서 필수, 급여명세서 선택
            ↓
[분석 진행]
  OCR → 구조화 → 문서 리뷰
            ↓
[문서 리뷰]
  결과 열람
  실제 근무 상황 자연어 입력(선택)
  동일 문서와 진술 재분석
            ↓
  ┌──────────────┴──────────────┐
  │                              │
[진정서 작성]                 [여기서 종료]
  │                              │
  ↓                              ↓
[누락 항목 문답]              [완료 화면]
  자연어 답변                    │
  미리보기 갱신                  └→ 처음부터 다시 시작
  │
  ↓
[진정서 완성]
  HWPX 다운로드
  │
  ├→ [여기서 종료] → [완료 화면]
  │
  └→ [관련 기관·신고처 확인]
                  ↓
             [기관 안내]
                  ↓
             [완료 화면]
                  ↓
             처음부터 다시 시작
```

## 3. 공통 화면 원칙

- 현재 초기화면의 통합 문서 업로드 방식을 유지한다.
- 사용자는 한 개의 통합 PDF 또는 여러 JPG·PNG·PDF를 업로드할 수 있다.
- 근로계약서는 필수이며, 급여명세서는 보유한 경우 함께 업로드한다.
- 급여명세서가 없으면 업로드를 차단하지 않고 분석 결과에 `급여 지급 여부 확인 제한`을 표시한다.
- 업로드 파일을 근로계약서와 급여명세서로 나누는 별도 진입 메뉴는 두지 않는다.
- 모든 사용자 선택은 버튼으로 명확하게 제공하고, 선택하지 않은 다음 단계로 자동 이동하지 않는다.
- 자연어 입력창은 문서 리뷰, 진정서 문답 및 기관 안내 단계에서 맥락에 맞게 동작한다.
- 종료를 선택해도 해당 세션의 분석 결과와 작성 결과를 완료 화면에서 확인할 수 있다.
- `처음부터 다시 시작`을 선택할 때만 현재 화면 상태를 초기화하고 새 분석 세션을 만든다.

## 4. 화면별 기능

### 4.0 언어 선택과 출력

크메르어, 네팔어, 베트남어, 인도네시아어, 미얀마어를 우선 지원한다. 한국어와 영어도 제공한다.

- 사용자가 헤더에서 선택한 언어 코드를 최초 문서 분석과 재분석 요청에 전달한다.
- 쉬운 설명과 사용자용 안내는 선택 언어를 우선한다.
- 계약서 원문, 법령명, 공식 기관명과 진정서 한국어 값은 원문 확인을 위해 한국어를 병기한다.
- 사용자 자연어가 선택 언어와 달라도 입력을 차단하지 않는다.
- 번역 결과가 법적 판정의 입력값을 덮어쓰지 않으며 판정에는 OCR 원문과 정규화된 값을 사용한다.

### 4.1 문서 업로드

기존 화면 구조를 유지한다.

- 안내: 근로계약서를 필수로, 급여명세서는 보유한 경우 함께 업로드하도록 설명한다.
- 입력: 근로계약서를 포함한 JPG, PNG, PDF 파일 한 개 이상
- 주요 동작:
  - 파일 선택 또는 다시 선택
  - 선택한 파일명 확인
  - 문서 분석 시작
- 오류:
  - 지원하지 않는 파일 형식
  - 빈 파일 또는 업로드 실패
  - OCR·분석 시간 초과
  - AI 서비스 요청 실패
- 실패 시 기존 파일을 유지하고 재시도 또는 다른 파일 선택을 제공한다.

### 4.2 분석 진행

다음 처리 상태를 순서대로 보여준다.

1. 문서 글자 읽기
2. 문서 정보 정리
3. 문제점과 대응 방법 만들기

사용자가 새 분석을 시작하거나 화면을 벗어나면 기존 요청을 취소한다.

### 4.3 문서 리뷰

- 분석 요약
- 임금·근로시간·휴일·업무·근무장소·숙식비·기타 공제 등 항목별 결과
- 현재 확인상 특이사항 없음, 추가 확인 필요, 주의 필요 상태
- 항목을 펼쳤을 때 원문 근거, 쉬운 설명 및 관련 기준 표시
- 계약서·급여명세서·사용자 진술의 값과 출처를 나란히 보여주는 비교표
- 고용주에게 전달할 한국어 확인 요청문과 사용자의 모국어 번역
- 현재 없는 출퇴근 기록·근무표·작업지시·지급내역 등 향후 증거 보관 안내
- 분석 결과에 대한 자연어 추가 설명과 질문

화면 하단에는 다음 선택지를 표시한다.

- `진정서 작성하기`
- `여기서 끝내기`

사용자가 실제 근무시간, 업무, 근무장소 또는 공제 사유를 자연어로 추가하면 프론트엔드는 최초 업로드 파일을 다시 선택하게 하지 않고 같은 세션에서 동일 파일과 누적된 사용자 설명을 문서 분석 API에 다시 전달한다. AI 서버는 변경하지 않고 기존 문서 분석 인터페이스의 `input.text`를 사용한다. 갱신된 결과는 이전 결과를 대체하되 문서 원문과 사용자 진술의 출처를 구분한다.

법률·절차에 대한 일반적인 후속 질문은 기존 AI 채팅 API를 사용한다. 일반 채팅 답변은 문서 비교 결과나 진정서 필드를 자동 변경하지 않는다.

다음 판단 제한을 모든 결과에 적용한다.

- 사용자 진술만 있는 사실은 `사용자 설명상` 또는 `추가 확인 필요`로 표시한다.
- 급여명세서가 없으면 수당 지급 여부와 정확한 미지급액을 확정하지 않는다.
- 근무기록이 없으면 사용자가 설명한 시간과 날짜를 주장값으로만 표시한다.
- 농축산업·어업 등 업종별 적용 특성과 사업장 조건을 확인하지 않고 일반 업종 기준을 확정 적용하지 않는다.
- 계약과 일치하거나 산술적으로 정상인 항목은 별도 정상 항목으로 보존하고 문제 카드로 만들지 않는다.

### 4.4 진정서 작성

지원 범위는 노동포털의 `진정서(체불, 직장 내 괴롭힘, 기타 노동법 위반)`, 민원 코드 `SN001`로 제한한다.

화면은 다음 영역으로 구성한다.

- ILLO의 현재 질문
- 자연어 답변 입력창
- 작성 진행률과 남은 필수 항목
- 현재까지 작성된 진정서 미리보기
- 미리보기 필드별 수정 버튼

백엔드가 필수 항목 중 비어 있는 값을 정해진 순서로 하나씩 질문한다. 사용자가 한 번에 입력한 답변은 현재 질문 중인 필드의 값으로 저장한다. 사용자가 미리보기에서 특정 항목을 선택해 수정하면 같은 입력창에 입력한 다음 답변을 그 필드의 새 값으로 저장한다.

입력값의 의미를 AI가 추측해 여러 필드로 자동 분리하지 않는다. 이메일·전화번호 등 형식이 명확한 값만 백엔드 규칙으로 검증한다.

### 4.5 진정서 필드

구현 시 공식 SN001 양식의 현재 필드명과 필수 여부를 기준으로 최종 대조한다. 서비스가 수집하는 항목은 다음 범주로 고정한다.

#### 진정인

- 성명
- 주소
- 일반 전화번호(선택)
- 휴대전화 번호
- 이메일
- 민원 처리상황 알림 수신 여부
- 처리 결과 전자문서 통지 여부

#### 피진정인 및 사업장

- 피진정인 성명
- 피진정인 연락처
- 사업체 구분: 사업장 또는 공사현장
- 회사명
- 회사 주소
- 실제 근무 장소
- 회사 전화번호
- 근로자 수(선택)

#### 진정 내용

- 근무 기간
- 임금 지급일과 실제 미지급 기간
- 계약 내용과 실제 지급·근무 조건의 차이
- 사용자가 요청하는 내용
- 첨부할 수 있는 증거자료 목록

문서 분석에서 확인된 사실은 진정 내용 미리보기의 참고 정보로 제시할 수 있지만, 사용자의 확인 없이 진정서 확정값으로 저장하지 않는다.

### 4.6 진정서 완성 및 다운로드

필수 항목이 모두 유효할 때만 진정서 완성 상태가 된다.

- `HWPX 초안 다운로드` 활성화
- `관련 기관·신고처 확인` 표시
- `여기서 끝내기` 표시

HWPX는 고용노동부가 배포한 공식 진정서 HWP를 Hancom Office로 HWPX 변환한 버전 고정 템플릿에 작성값을 삽입해 생성한다. 표, 여백, 페이지 배치와 제목은 공식 원본을 유지한다.

파일 화면과 다운로드 안내에는 다음 문구를 표시한다.

> 이 파일은 제출 전 확인과 수정을 위한 진정서 초안입니다. 파일을 내려받는 것만으로 신고가 접수되지 않습니다.

### 4.7 관련 기관·신고처

이 화면은 사용자가 `관련 기관·신고처 확인`을 선택했을 때만 표시한다.

| 안내 대상 | 제공 정보 | 사용자 동작 |
| --- | --- | --- |
| 고용노동부 노동포털 | SN001 설명 및 온라인 신청 페이지 | 새 창에서 공식 페이지 열기 |
| 지방고용노동관서 | 사업장 소재지 관할 관서 찾기 | 공식 관서 검색 페이지 열기 |
| 고용노동부 고객상담센터 | 1350, 유료, 평일 09:00~18:00 | 전화 가능 기기에서 전화 연결 |
| 외국인력상담센터 | 1577-0071, 모국어 고충상담 | 전화 가능 기기에서 전화 연결 |
| EPS·관할 고용센터 | 근무장소·업무·사업장 변경 관련 확인 | 공식 EPS와 고용센터 검색 페이지 열기 |

기관명, URL, 전화번호와 운영시간은 백엔드의 고정된 공식 기관 목록에서 제공한다. AI 답변을 기관 카드의 데이터로 사용하지 않는다. 분석 결과의 문제 유형에 따라 다음과 같이 우선순위를 정한다.

- 임금·연장·야간·휴일수당·공제: 1350, 지방고용노동관서, 노동포털
- 업무·근무장소·사업장 변경: 외국인력상담센터, EPS, 관할 고용센터
- 두 유형이 함께 있으면 양쪽 기관을 모두 표시하되 역할을 구분한다.

기관 안내 중 자연어 질문은 기존 AI 채팅 API를 사용할 수 있지만, 화면의 공식 링크와 연락처는 변경하지 않는다.

### 4.8 완료

- 사용자가 확인한 문서 리뷰 결과를 유지한다.
- 작성한 경우 진정서 미리보기와 HWPX 재다운로드를 유지한다.
- 기관을 확인한 경우 공식 기관 카드도 유지한다.
- `처음부터 다시 시작`을 누르면 화면 상태를 초기화하고 새 세션으로 돌아간다.

## 5. 상태와 분기

프론트엔드는 다음 상태를 기준으로 화면을 렌더링한다.

| 상태 | 진입 조건 | 허용 동작 |
| --- | --- | --- |
| `UPLOAD` | 최초 진입 또는 재시작 | 파일 선택, 분석 시작 |
| `ANALYZING` | 분석 요청 성공 | 진행 확인, 요청 취소 |
| `REVIEW` | 분석 완료 | 추가 질문, 진정서 시작, 종료 |
| `REVIEW_UPDATING` | 실제 근무 상황을 추가해 재분석 | 진행 확인, 기존 결과 유지 |
| `DRAFTING` | 진정서 작성 선택 | 현재 필드 답변, 기존 필드 수정 |
| `DRAFT_READY` | 필수 필드 완료 | HWPX 다운로드, 기관 확인, 종료 |
| `AGENCY` | 기관 확인 선택 | 공식 링크 열기, 추가 질문, 종료 |
| `COMPLETED` | 사용자가 종료 선택 | 결과 확인, 재다운로드, 재시작 |

이동할 수 없는 상태로 직접 접근하면 현재 세션에 존재하는 가장 마지막 유효 상태로 복원한다.

## 6. 서버 역할과 API 초안

AI 서버는 변경하지 않는다. 기존 문서 분석과 채팅 인터페이스만 사용한다.

Spring Boot 백엔드는 다음을 담당한다.

- 분석 `sessionId` 유지
- 선택 언어와 업로드 문서를 같은 화면 세션에서 유지
- 자연어 근무 설명을 누적해 동일 문서 재분석
- SN001 필드와 질문 순서 관리
- 답변 저장과 입력 검증
- 완성 여부 계산
- 공식 기관 목록 제공
- 공식 양식형 HWPX 생성

### 6.0 최초 분석과 자연어 재분석

기존 비동기 문서 분석 API를 유지하면서 선택 언어를 추가한다.

```http
POST /api/sessions/{sessionId}/contract-analyses
Content-Type: multipart/form-data
```

- `files`: 최초 업로드 파일. 재분석할 때 프론트엔드가 같은 파일을 다시 전송한다.
- `text`: 최초 분석 요청 또는 지금까지 누적된 실제 근무 상황 설명
- `language`: 사용자가 선택한 출력 언어 코드

최초 분석과 재분석은 같은 `sessionId`를 사용한다. 재분석에 실패하면 이전에 성공한 결과를 유지한다.

### 6.1 진정서 초안 생성

```http
POST /api/sessions/{sessionId}/complaint-drafts
```

```json
{
  "formId": "SN001"
}
```

### 6.2 진정서 조회

```http
GET /api/sessions/{sessionId}/complaint-drafts/SN001
```

주요 응답 데이터:

```json
{
  "formId": "SN001",
  "status": "DRAFTING",
  "currentField": "petitionerName",
  "question": "이름을 입력해주세요.",
  "fields": [],
  "missingFields": [],
  "complete": false
}
```

### 6.3 자연어 답변 또는 수정

```http
POST /api/sessions/{sessionId}/complaint-drafts/SN001/answers
```

```json
{
  "fieldKey": "petitionerName",
  "content": "김민수"
}
```

- `fieldKey`가 없으면 서버의 현재 질문 필드를 사용한다.
- 수정할 때는 프론트엔드가 사용자가 선택한 `fieldKey`를 전달한다.
- 성공 응답에는 갱신된 전체 초안과 다음 질문을 반환한다.

### 6.4 HWPX 다운로드

```http
GET /api/sessions/{sessionId}/complaint-drafts/SN001/download
```

- 필수 항목이 남아 있으면 `COMPLAINT_DRAFT_INCOMPLETE`를 반환한다.
- 완성된 경우 HWPX MIME 타입과 다운로드 파일명을 반환한다.

### 6.5 기관 목록

```http
GET /api/support-channels?issueTypes=UNPAID_WAGE,WORKING_CONDITION_VIOLATION
```

- 지원하지 않는 문제 유형은 `UNSUPPORTED_ISSUE_TYPE`을 반환한다.
- 연락처와 링크는 고정된 공식 데이터만 반환한다.

모든 JSON 성공·실패 응답은 프로젝트 공통 형식인 `{ "code": string, "data": object }`를 사용한다.

## 7. 오류 처리

| 상황 | 사용자 안내 | 화면 처리 |
| --- | --- | --- |
| 문서 분석 실패 | 문서를 분석하지 못했으며 재시도할 수 있음을 안내 | 파일 유지, 재시도 표시 |
| AI 추가 질문 실패 | 잠시 후 다시 시도하도록 안내 | 기존 리뷰 결과 유지 |
| 필수값 누락 | 누락된 항목을 구체적으로 안내 | 해당 필드로 이동 |
| 형식 오류 | 필요한 형식의 예시 제공 | 기존 입력 유지 |
| HWPX 생성 실패 | 초안이 저장되어 있으며 다시 다운로드할 수 있음을 안내 | 작성 화면 유지 |
| 기관 목록 조회 실패 | 노동포털·1350 기본 정보를 재시도 가능 상태로 표시 | 진정서 결과 유지 |
| 세션 없음 | 이전 상태를 복원할 수 없음을 안내 | 새로 시작 제공 |

## 8. 서비스 명칭

사용자에게 보이는 다음 항목을 `ILLO`로 통일한다.

- 웹 헤더
- 브라우저 제목
- 접근성용 서비스명
- 루트 README
- Swagger/OpenAPI 제목과 설명

Java 패키지명, Gradle 프로젝트명, npm 패키지명과 Python 모듈명 등 내부 식별자는 변경하지 않는다.

## 9. 구현 범위와 제한

### 구현 대상

- 프론트엔드 화면 상태와 실제 API 연결
- 제조업·건설업·서비스업·농축산업·어업 문서 및 사용자 진술 비교 화면
- 5개 모국어와 한국어·영어 선택 전달
- Spring Boot 진정서 상태·검증·기관 데이터·HWPX 생성
- 사용자 노출 ILLO 브랜딩
- 관련 Swagger와 테스트

### 구현 제외

- `ai/` 디렉터리의 코드와 설정 변경
- 상담사 또는 전문가 실시간 연결
- 노동포털 자동 로그인·본인인증·신고 제출
- 외부 기관 API 연동
- SN001 이외의 민원서식
- AI가 자유문장에서 여러 진정서 필드를 임의 추출하는 기능
- 사건 접수 후 진행상태 추적

## 10. 정성 테스트 수용 기준

T01~T10은 문서 진단과 자연어 비교의 기준 시나리오로 사용한다. 각 테스트는 선택 언어, 업로드 문서, 자연어 입력 시점, 기대 문제와 정상 항목을 함께 검증한다.

| 테스트 | 핵심 비교 | 필수 기대 결과 |
| --- | --- | --- |
| T01 | 계약 기본급 230만 원 ↔ 명세서 210만 원 | 차액 20만 원, 다른 합계 정상 |
| T02 | 계약 고정 식대 10만 원 ↔ 명세서 항목 없음 | 누락 가능성, 기본급 정상 |
| T03 | 계약 18시 종료 ↔ 진술 20시 종료·18일 ↔ 연장수당 없음 | 약 36시간 주장, 기록 확인 필요 |
| T04 | 야간 4시간×8일 진술 ↔ 야간수당 없음 | 약 32시간 주장, 동의 여부 확정 금지 |
| T05 | 계약 숙식비 25만 원 ↔ 명세서 45만 원 | 숙박 15만 원·식비 5만 원 차이 |
| T06 | 계약 07~17시 ↔ 진술 06~19시, 명세서 없음 | 하루 약 3시간 차이, 체불액 확정 금지 |
| T07 | 계약상 일요일 휴일 ↔ 4일·32시간 진술 ↔ 수당 없음 | 휴일 성격과 기록 추가 확인 |
| T08 | 계약 자재 운반·정리 ↔ 반복 철거작업 진술 | 업무 차이와 안전자료 확인 필요 |
| T09 | 계약 A농장 ↔ 주 3일 B농장 진술 | 장소 차이, 고용센터 사실확인 안내 |
| T10 | 최저임금·연장수당·브로커비 복합 | 문제 3개 분리, 숙소비 정상 보존 |

공통 합격 조건은 다음과 같다.

- OCR과 구조화 값이 Ground Truth와 일치한다.
- 문서 값과 사용자 진술의 출처를 혼합하지 않는다.
- 문제 수치와 정상 수치를 모두 보존한다.
- 사용자 진술이나 누락 문서만으로 법 위반과 정확한 체불액을 확정하지 않는다.
- 사용자가 선택한 모국어 설명과 한국어 원문을 함께 제공한다.
- 문제 유형에 맞는 확인 요청문, 증거 보관 안내와 공식 기관을 제공한다.

진단 테스트와 별도로 다음 서비스 흐름 E2E 테스트를 수행한다.

```text
업로드
→ 1차 리뷰
→ 자연어 실제 상황 입력 및 재분석
→ 진정서 작성 선택
→ SN001 필드 문답·수정
→ HWPX 다운로드
→ 기관 확인 선택
→ 종료 및 처음부터 다시 시작
```
