# 브라우저 내 계약서 민감정보 수동 가림 구현 계획

> 상태: 수동 마스킹 MVP 구현 완료. OCR 및 자동 민감정보 탐지는 범위에서 제외한다.

## 1. 목적

사용자가 근로계약서나 급여명세서를 서버에 전송하기 전에 브라우저에서 직접 민감정보를
가린다. 원본은 서버로 보내지 않고, 사용자가 확인한 검은색 마스킹이 픽셀에 반영된 익명화
이미지만 기존 분석 API에 전달한다.

이 기능은 자동 탐지의 정확도를 전제로 하지 않는다. 문서 양식, 촬영 각도, 해상도와 언어가
달라도 사용자가 화면을 보고 필요한 영역을 직접 지정하는 방식을 사용한다.

## 2. 사용자 흐름

```text
문서 선택(JPG/PNG/PDF)
→ 브라우저에서 페이지 렌더링
→ 각 페이지의 민감정보 영역을 드래그해 추가
→ 잘못 지정한 영역 삭제
→ 모든 페이지 확인
→ 검은색 마스킹을 이미지 픽셀에 반영
→ 익명 파일명의 JPEG 생성
→ 기존 문서 분석 API 전송
```

- 페이지 이동과 확대·축소를 제공한다.
- 마우스나 터치 드래그로 영역을 추가한다.
- 키보드 사용자는 기본 크기의 가림 영역을 추가한 뒤 삭제·재지정할 수 있다.
- 모든 페이지를 확인하기 전에는 분석 요청을 보낼 수 없다.
- 취소하면 생성한 Object URL과 메모리 상태를 정리하고 초기 화면으로 돌아간다.

## 3. 지원 범위

### 포함

- JPG, JPEG, PNG, PDF 렌더링
- 직사각형 수동 마스킹 추가와 삭제
- 페이지별 확인 상태
- 페이지 이동 및 확대·축소
- 불투명 검은색 픽셀 마스킹
- 익명 파일명으로 JPEG 재생성
- 파일당 10MB 제한
- 모바일·데스크톱 반응형 검토 화면
- 원본 Object URL과 캔버스 메모리 정리

### 제외

- 브라우저 OCR
- 이름·번호·주소 등의 자동 탐지 또는 자동 후보 표시
- 문서 양식별 좌표 템플릿
- 원본 파일의 서버 저장 또는 전송
- 원래 PDF 구조를 유지한 재생성
- 마스킹 실패 시 원본을 대신 전송하는 동작

## 4. 사용자가 가려야 할 정보

- 주민등록번호, 외국인등록번호, 여권번호 등 식별번호
- 전화번호와 이메일
- 근로자 및 개인 사업주의 이름
- 개인 주소와 상세 거주지
- 계좌번호
- 생년월일
- 서명, 도장, 얼굴 사진

다음 계약 분석 정보는 원칙적으로 남긴다.

- 계약기간과 체결일
- 임금, 수당, 공제액과 지급일
- 근로시간, 휴게시간과 휴일
- 업무, 업종, 숙식 제공 조건
- 법인명, 사업장명과 실제 근무장소

법인명이나 사업장 주소가 개인 식별정보를 포함하는 경우 사용자가 직접 판단해 추가로 가릴 수
있다. 화면 안내문은 자동으로 모두 찾았다고 표현하지 않고, 사용자가 전송 전 직접 확인하도록
명확히 안내한다.

## 5. 보안 원칙

- 원본 파일은 브라우저 메모리에서만 처리한다.
- 검토가 끝나기 전 네트워크 요청을 보내지 않는다.
- 서버에는 마스킹이 픽셀에 반영된 가공본만 전송한다.
- 원본 파일명 대신 세션 내에서 생성한 익명 파일명을 사용한다.
- 원본 파일과 민감정보를 콘솔, 분석 이벤트 또는 오류 로그에 기록하지 않는다.
- 처리 실패 시 전송을 중단하며 원본으로 대체하지 않는다.

## 6. 렌더링 및 좌표 처리

- PDF는 `pdfjs-dist`로 페이지별 캔버스에 렌더링한다.
- 이미지 파일은 디코딩한 뒤 페이지 캔버스에 그린다.
- 마스킹 좌표는 화면 픽셀이 아니라 페이지 기준 정규화 좌표로 저장한다.
- 확대·축소나 반응형 레이아웃 변경 후에도 같은 문서 위치를 가리도록 좌표를 변환한다.
- 내보낼 때 원본 렌더 해상도 기준으로 좌표를 복원해 불투명 사각형을 그린다.

## 7. 검토 화면

검토 화면은 다음 요소로 구성한다.

- 현재 페이지와 전체 페이지 수
- 이전/다음 페이지 이동
- 확대·축소
- 문서 캔버스와 드래그 가능한 오버레이
- 현재 페이지에 추가한 영역 목록과 삭제 버튼
- 페이지 확인 체크
- 취소 및 익명화 후 분석 버튼

안내 문구 예시:

> 이름, 번호, 개인 주소, 계좌번호, 서명과 도장처럼 서버에 보내지 않을 정보를 직접 드래그해
> 가려 주세요. 모든 페이지를 확인한 뒤 분석을 시작할 수 있습니다.

## 8. 내보내기와 API 연결

1. 원본 렌더 캔버스를 새 출력 캔버스에 복사한다.
2. 사용자가 지정한 모든 영역을 불투명 검은색으로 채운다.
3. JPEG Blob으로 인코딩한다.
4. 원본 이름과 무관한 익명 파일명을 생성한다.
5. 기존 multipart 분석 요청의 파일 파트로 전달한다.

여러 페이지 PDF는 페이지별 JPEG로 전송한다. 가공본 생성에 실패하면 분석 요청을 보내지 않고
사용자에게 재시도 또는 취소를 안내한다.

## 9. 오류 처리

| 상황 | 동작 |
| --- | --- |
| 지원하지 않는 파일 | 기존 파일 형식 오류를 표시한다. |
| 10MB 초과 | 기존 파일 크기 오류를 표시한다. |
| PDF/이미지 렌더링 실패 | 전송하지 않고 재선택을 안내한다. |
| 페이지 미확인 | 분석 버튼을 비활성화하고 남은 페이지를 안내한다. |
| 가공본 생성 실패 | 원본을 전송하지 않고 오류를 표시한다. |
| 사용자가 취소 | 메모리와 Object URL을 정리하고 초기 화면으로 돌아간다. |

## 11. 검증

```bash
cd frontend
npm test
npm run lint
npm run build
```

브라우저에서는 최소한 다음을 직접 확인한다.

- JPG/PNG 한 장과 다중 페이지 PDF가 열리는지
- 회전되거나 비스듬히 촬영된 문서에도 원하는 위치를 직접 가릴 수 있는지
- 확대·축소 후에도 가림 영역이 같은 위치에 남는지
- 각 페이지를 확인해야만 분석할 수 있는지
- 전송되는 파일에서 지정한 정보가 실제 픽셀로 가려졌는지
- 원본 파일명과 원본 파일이 요청에 포함되지 않는지
- 취소와 재선택이 정상 동작하는지
- 모바일 화면에서 드래그와 페이지 이동이 가능한지

## 12. 완료 기준과 제한사항

- 사용자가 모든 페이지에서 필요한 영역을 직접 추가·삭제할 수 있다.
- 확인하지 않은 페이지가 있으면 전송할 수 없다.
- 지정한 영역이 가공본 픽셀에 불투명하게 반영된다.
- 서버에는 익명 파일명의 가공본만 전송된다.
- 자동 탐지를 제공하거나 완전한 비식별화를 보장한다고 안내하지 않는다.

수동 방식도 사용자가 영역을 놓칠 수 있으므로 완전한 개인정보 제거를 보장하지 않는다. 서비스는
전송 전 최종 확인 책임과 누락 가능성을 화면에 명시해야 한다.
